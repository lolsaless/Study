# 연구사업 지침 (수질TMS·하천 측정망)

## 1. 연구 개요
- 2027 연구사업. 예산 삭감으로 실험 없이 공개·수집 자료 분석만으로 논문·연구 실적을 낸다(팀·기관에 중요한 실적). 목표: 2~3개월 안에 논문 1편 투고 + 2027년 연구사업 계획서.
- 자료: 경기도 하·폐수처리시설 방류수 TMS 일자료(pH·TOC·SS·T-N·T-P 농도와 배출량, 2024-01~2026-06), 국가 수질자동측정망 시간·일자료, 물환경 수질측정망(한강, 월 1~4회 채수), 기상청 ASOS·한강홍수통제소 기온·강수·수위·유량.
- 참고 방향: Lu et al. 2021(Sci. Total Environ., 처리장 군집 방류수 시계열 거동).

## 2. 현재 위치 (2026-11-24 기준, 자세한 숫자는 진행현황 문서)
- 범위: **한탄강 수계**(2026-11-13 축소). 양주·동두천·포천·연천 사업장 30곳, 측정망 포천·한탄강·신천·미산.
- 끝난 것: 수집·정제(h), 기본 분석(a01~a07), 기초 점검(b01~b04), 물질수지 강화·예측(m01~m06), 발표자료(문서형 + 발표 모드 + 편집 모드, 11-23), 전체 재검토(무방류일 처리, 요일 리듬 발견), 폴더 구조 개편(11-17), 측정망·기상·수위 수집 코드 정리(11-17~18).
- 논문의 중심: 물질수지(처리수 기여율·합류점 수지·부하 3분할)와 요일 리듬(주간 진폭으로 본 전달률). 예측 모형은 보조.
- 경기도 전체 분석(tms_analysis_1~3 포함)은 끝난 단계로 참고만 한다.

## 3. 내가 답을 얻고 싶은 질문
1. 하천 수질에서 하·폐수 처리수가 차지하는 몫은 얼마인가(지점·항목·계절·유황별)?
2. 처리수가 아닌 오염원(TMS 밖 배출원, 비 올 때의 비점오염)의 영향은 얼마인가?
3. 처리장 방류가 하천 측정망까지 얼마나, 며칠 만에 전달되는가? 요일 리듬은 왜 생기는가?
4. 어느 처리장을 얼마나 줄이면 어느 지점이 얼마나 좋아지는가(저감 시나리오)?
5. 방류수질·하천 수질을 며칠 앞까지 예측할 수 있는가(난도 있는 모델링)?
6. 평가점수로 관리 우수/미흡 시설을 구분해 정책 제안으로 이을 수 있는가?
7. 이 틀을 다른 수계로 넓힐 수 있는가?

### 5-3. 기기·환경
- **주 작업: 맥미니(Apple Silicon) + 윈도우 노트북.** 업무 PC는 Windows+Edge(행정망, 인터넷 제한). 인텔 맥은 거의 쓰지 않으므로 기준으로 삼지 않는다.
- 코드는 맥미니·윈도우 둘 다에서 돌아가야 한다: 경로는 `pathlib`, 파일 인코딩은 `utf-8-sig`(엑셀 호환), 한글 경로·파일명은 NFC 정규화(`C.find()`), 셸 명령 대신 Python으로, 줄바꿈·대소문자 차이 주의. 브라우저용 HTML은 크롬·엣지 기준.
- 라이브러리는 `requirements.txt`에 버전 범위를 둔다. 지금 상한(numpy<2.3, pandas<2.3, scikit-learn<1.7 등)은 인텔 맥 때문에 정한 것이라 꼭 유지할 필요는 없지만, 올릴 때는 결과 CSV가 같은지 확인한 뒤 올린다.
### 5-4. 비밀값·git
- 인증키(`*.env`, `api_keys.env`)는 읽거나 출력하거나 커밋하지 않는다. 새 폴더에는 `.gitignore`(`*.env`)를 먼저 만든다. 대용량 원본(shp·geojson·xlsx)도 커밋하지 않는다.
- 커밋·푸시는 내가 요청할 때만 한다(git 저장소는 `Study`뿐).
### 5-5. 검증
- 폴더가 연결된 대화에서는 Claude가 복사본에서 실행해 개편·수정 전후 결과를 비교하고, 사용자 폴더의 결과 그림은 덮어쓰지 않는다. 최종 확인은 내가 맥미니(또는 윈도우)에서 `python run.py`로 한다. 폴더가 연결되지 않은 대화에서는 코드를 실행했다고 쓰지 않는다.

## 6. 분석·해석
- 각 분석은 "왜 하는가 → 방법 → 결과 읽는 법 → 한계(기간·표본 수·결측)"를 함께 쓴다. 이 분야 초보라 쉬운 해석을 붙인다.
- 측정값 품질부터 본다. 0·ND는 처리 방식을 명시한다(네 항목이 모두 0인 날 = 무방류일로 부하·유량 0, 한 항목만 0인 값의 의미는 미확인). 물리적으로 불가능한 값·이상치는 표시만 하고 임의로 고치지 않는다.
- 요일 효과를 먼저 뺀 뒤 상관·예측 성능을 본다(요일 보정 기준과 견준다).
- 확인한 것 / 추정한 것 / 미검증을 구분해 쓴다. 가정값(유량·부하 오차 등)은 가정이라고 적는다.
- 연구 아이디어는 새로움, 자료로 가능한지, 소요 시간, 논문 가치로 비교해 제안한다. 문헌은 실제 존재를 검색으로 확인한 것만 인용한다.

## 7. 보고 자료
- 부서장 설득용 HTML 발표 문서: 단계별 코드·결과·그래프·쉬운 해석·확장 가능 영역. 원본은 부품(`presentation/pages/*.md`)과 `부품설명서.md`다. 글은 HTML의 편집 모드(크롬·엣지)에서 고쳐 md에 저장하고, 숫자·그래프 반영은 `python run.py deck`으로 다시 만든다. HTML 파일 자체는 직접 고치지 않는다.
- 지도는 VWorld로 하천 측정망·배출사업소를 부하량 크기·색으로 표시하고, 수계 바탕도는 `Data/지도/`(실폭하천)를 쓴다. API 키는 `.env`로 분리하고 밖으로 내보내지 않는다.
