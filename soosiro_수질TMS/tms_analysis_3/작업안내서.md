## 0. 30초 요약

```
[원자료]  data/raw/…  (받은 그대로, 수정 금지)          ← 물환경정보시스템 xlsx, 기상청·홍수통제소 CSV, API 수집 결과
   │ 01_ingest_nier.py(수질 xlsx)  /  02_ingest_aux.py + ingest/mappings/*.json(그 밖의 모든 자료)
   ▼
[표준 자료] data/standard/… + data/meta/stations.csv   ← 분석 코드는 '여기만' 읽는다(양식: python -m core.schema)
   │ 00_check_inputs.py → 어떤 분석이 실행 가능한지 표시
   ▼
[분석]  10~13 기본 → 20~25 중급 → 30~38 심화 → 40~42 연계   (run_all.py 로 단계별 실행)
   ▼
[결과]  results/<번호>/summary.md·CSV·그림  →  90번이 results/00_핵심결과.md · 00_DIGEST_for_Claude.md · zip 생성
```

**핵심 원칙: 새 자료는 '분석 코드'를 고치는 게 아니라 '표준 양식으로 바꾸는 매핑(JSON)'만 추가한다.**
양식만 맞으면 기존 분석 30여 개가 그대로 돈다.

### 3-E. 새 분석 추가

`ingest` 와 같은 원칙: 표준 자료만 읽고, `core` 의 함수를 쓰고, 결과는 `Report` 로 남긴다. 뼈대:

```python
# -*- coding: utf-8 -*-
"""
3X. 분석 제목 — 한 줄 설명(00번 표에 그대로 표시됨)
"""

from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parent))
import pandas as pd
import config as C
from core import Report, io, st

REQUIRES = ["river_daily"]        # 필요한 표준 자료(00·run_all 이 읽음). 연계면 "weather_link" 등 추가
LEVEL = "심화"                    # 기본/중급/심화/연계

def main():
    rep = Report("3X_name", "3X. 분석 제목", level=LEVEL, purpose="무엇을 왜 보는가")
    d = io.load_daily(["TOC", "TP"])          # 품질 D 등급은 자동 제외
    rep.data_info(d)
    ...                                        # 계산
    rep.table(df, "표 제목"); rep.csv(df, "파일.csv"); rep.fig(fig, "그림.png")
    rep.finding("숫자가 들어간 핵심 결과 한 줄")   # → 00_핵심결과.md 에 모임
    rep.save()

if __name__ == "__main__":
    main()
```

번호 규칙: 0x 준비 · 1x 기본 · 2x 중급 · 3x 심화 · 4x 연계 · 9x 취합. 파일명이 `NN_이름.py` 이면 run_all 이 자동으로 포함한다.

## 4. 지켜야 할 규칙

**자료**
1. `data/raw/` 의 원자료는 절대 고치지 않는다(고칠 일은 매핑의 `rename_values`·`filters`·`scale` 로).
2. 결측은 빈칸. 0 을 넣지 않는다(기상청 강수처럼 '빈칸=0'인 출처는 매핑의 `fillna` 로 명시).
3. 날짜 `YYYY-MM-DD`, 시각 `YYYY-MM-DD HH:MM`. 24시 표기는 매퍼가 다음날 0시로 바꾼다.
4. 측정소 이름은 `stations.csv` 와 **글자 하나까지** 같게(다르면 `config.STATION_ALIAS` 또는 매핑 `rename_values`).
5. 단위는 표준 양식의 단위로(예: μg/L 은 `scale` 0.001 로 mg/L).
6. 인증키는 `data/api_keys.env` 에만. 코드·문서·커밋에 키를 쓰지 않는다.
7. 추정·가설로 채운 값은 `link_note` 등에 '추정'으로 남긴다.

**분석·해석**
1. 일자료 검정은 자기상관 때문에 p 값이 과대평가된다 → 측정소 단위 검정(13), 블록 부트스트랩(12), FDR 보정을 쓴다.
2. 현재 자료는 **2024–2025 두 해**다. 추세(21)·극값 재현값(35)·예측(37)은 '예비'로 읽고, 연도가 쌓이면 다시 돌린다.
3. 법정 기준값(`config.RIVER_STD`, `LAKE_STD`)과 조류 기준(`BLOOM_CHLA`)은 현행 법령·지침과 대조 후 쓴다.
4. 결과 문장은 `rep.finding()` 에 숫자와 함께 쓰고, 해석의 한계는 summary.md 본문에 적는다.

**Claude 작업 규칙**
1. 이 문서 → PROJECT_STATUS.md → results/00_핵심결과.md 순서로 읽고 시작한다.
2. 새 자료는 매핑(3-C)으로 붙이고, 분석 코드를 자료 형식에 맞춰 고치지 않는다.
3. 코드를 바꾸면 해당 스크립트를 실제로 실행해 `[완료]` 와 핵심 결과를 확인한 뒤 보고한다.
4. 끝나면 PROJECT_STATUS.md 를 갱신하고, README 의 표(스크립트 목록)를 새 파일과 맞춘다.

## 5. 자주 생기는 문제

| 증상 | 원인·해결 |
|---|---|
| 그림의 한글이 □ | 맑은 고딕·AppleGothic·나눔고딕 중 하나가 필요(Mac 은 기본 있음) |
