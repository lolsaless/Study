# 한탄강 연구 수계지도 부품지도

## 지금 만들 수 있는 지도

국토지리정보원 「전국 연속수치지형도 코드 및 레이어 설명서」 v5.1.1의 2쪽(명명 규칙), 9쪽(레이어 목록), 120쪽(지형지물 정의)을 확인했다. `N3A_E0032111`은 1:5,000 **실폭하천** 면 레이어다. 설명서의 속성은 `UFID`(객체 식별자), `SCLS`(통합코드), `FMTA`(제작정보)다. 중권역별 추출에는 별도의 유역 경계 데이터가 필요하다. 실폭하천의 면만으로는 상·하류 연결, 흐름 방향, 시설의 실제 방류구를 판정할 수 없다.

| 받은 파일 | 역할 |
|---|---|
| `N3A_E0032111.shp` (350 MB) | 하천 면 도형 |
| `N3A_E0032111.shx`, `.dbf`, `.prj` | 도형 인덱스, 속성, 좌표계. 같은 이름으로 같은 폴더에 둔다. |
| `N3A_E0032111.geojson` (981 MB) | 이번 작업의 입력은 Shapefile 세트다. |
| `연속수치지형도_데이터_설명서.pdf` | 레이어 코드와 표준 속성의 근거 |

작업 준비 단계에서는 파일 목록과 작은 `.prj`만 확인했다. `.prj`는 Korea 2000 통합좌표계(EPSG:5179에 해당)로 해석되며, 실행 시에는 GDAL이 원본 좌표계를 읽는다. 지점 CSV의 위경도와 내보내는 GeoJSON에는 WGS84를 적용한다.

## 연구 범위를 정하는 순서

1. **지도 초안**을 먼저 만든다. `00_설정/site_basin.csv`의 38행 중 `in_scope=1`인 30곳(한탄강 28, 임진강 상류 1, 임진강 하류 1)을 기본 표시한다. EPSG:5179에서 지점 전체를 감싸는 사각형의 각 변을 기본 3 km 확장한다. 이 사각형 안의 실폭하천 면에는 인접 유역의 하천이 포함될 수 있고, 대상 유역의 먼 상류는 잘릴 수 있다.
2. **연구용 유역 범위**를 확정한다. 출처와 기준연도가 확인되는 공식 유역 경계 자료에서 지점 좌표와 유역 폴리곤을 공간 조인하고, 한강수계 안의 대상 구역 코드 또는 분석 목적에 맞는 범위로 경계 파일을 만든다. `midbasin_auto`는 연결표의 참고값이다. 좌표 기반 유역 소속과 방류수 이동 경로는 각각 확인한다. 임진강 상·하류 지점 포함 여부는 연구 범위에서 명시한다.
3. 선택된 경계만 담은 단일 폴리곤 레이어를 `--basin`에 넣어 다시 실행한다. 선택 지점이 경계 밖에 있으면 스크립트가 지점명을 표시하고 종료한다. 전국 유역 파일을 그대로 넣으면 선택 영역 자체가 전국이 될 수 있으므로 먼저 대상 구역을 추린다.
4. 결과를 GIS나 브라우저에서 확인한다. 지점 수와 위치, 하천 면의 누락·과다 추출, 유역 경계와의 관계를 확인한다. 지점이 시설 좌표로 등록된 경우 하천 면에 겹치지 않을 수 있다. 시설의 실제 방류 위치나 수질측정망을 추가하려면 검증된 좌표를 별도 레이어로 관리한다.

## 부품지도

| 부품 | 책임 | 바꿀 때 |
|---|---|---|
| `00_설정/site_basin.csv` | 연구 지점, 위경도, 연구 포함 여부, 연결표 속성 | 지점 목록 또는 위치를 확정할 때 |
| `extract_river_map.py`의 `read_sites` | UTF-8 BOM CSV 읽기, 지점 선택, 좌표 검증 | 다른 CSV의 열 이름이나 선택 조건을 쓸 때 |
| `make_area` | 미리보기 사각형 생성 또는 대상 유역 경계 결합 | 연구 범위 정의를 바꿀 때 |
| `extract_rivers` | 원본 CRS의 범위로 후보 조회, 도형 보정과 면 클립, WGS84 변환 | 다른 실폭하천 Shapefile 또는 보존 속성을 쓸 때 |
| `render_map` | 실폭하천·범위·지점 표시, 지점명과 연결표 정보 표시 | 색상과 팝업을 바꿀 때 |
| `requirements-map.txt` | 지도용 Python 의존성 | 지도 실행 환경을 따로 설치할 때 |

원본 Shapefile에서는 먼저 GDAL 공간 필터로 후보만 파이썬에 가져온다. 이번 파일 목록에 별도 공간 인덱스 `.qix`가 없어 GDAL이 디스크에서 도형을 순회할 수 있다. `.shx`는 레코드 위치 인덱스다. 반복 작업에서 느리면 원본의 작업 사본에 공간 인덱스를 구성한 뒤 비교한다.

## 실행

VS Code에서 `extract_river_map.py`를 열고 오른쪽 위의 **Run Python File**을 누른다. 아래 터미널의 입력란에 여유 폭을 km 단위로 입력한다. 예를 들어 `10`을 입력하면 지점 전체를 감싸는 사각형을 각 방향으로 10 km 늘린다. Enter만 누르면 기본 3 km를 사용한다.

터미널에서 직접 실행할 때는 아래 명령을 사용한다. Python 3.10 이상이 필요하다.

```bash
cd "$HOME/Documents/GitHub/Study/Data/지도"
python3 extract_river_map.py
```

1. 코드가 같은 폴더의 `requirements-map.txt`를 읽는다. 현재 Python에 필요한 버전이 모두 있으면 설치를 건너뛴다. 부족하면 지도 폴더에 `.venv-map`을 만들거나 기존 환경을 재사용하고, 그 환경에 필요한 패키지를 설치한다. 첫 설치에는 인터넷 연결이 필요하다.
2. 인자 없이 대화형 터미널에서 실행하면 여유 폭을 먼저 입력한다. 이어서 파일 선택창에서 저장 위치에 관계없이 실폭하천 `N3A_E0032111.shp`를 선택한다. 같은 이름의 `.shx`, `.dbf`, `.prj`는 SHP 옆에 있어야 한다. 선택을 취소하면 추출 없이 종료한다.
3. 결과는 `output/river_map_날짜_시각`에 저장된다. 터미널에 표시된 폴더의 `map.html`을 브라우저에서 연다.

기본 지점 목록은 기존 연구 폴더의 `analysis_hantan_river/00_설정/site_basin.csv`를 직접 읽는다. 지도 폴더에 `site_basin.csv`를 두면 그 파일을 우선 사용한다. 다른 CSV는 `--sites "/경로/지점.csv"`로 지정한다. 필수 열은 `site,lat,lon,in_scope`이며 `--all-sites`를 쓰면 `in_scope` 없이도 실행할 수 있다. `type,midbasin_auto,receiving_station`은 선택 열이다.

- 확정된 유역으로 자르려면 `python3 extract_river_map.py --basin "/경로/대상유역.gpkg"`를 실행한다. CRS가 정의된 단일 레이어 폴리곤 파일을 사용한다.
- 파일 선택창을 생략하려면 `--river-shp "/경로/N3A_E0032111.shp"`를 추가한다.
- 미리보기 여유 폭은 `--margin-m`으로, 결과 저장 위치는 `--out`으로 지정한다. `--out`은 아직 존재하지 않는 경로를 사용한다.

| 결과 | 사용처 |
|---|---|
| `map.html` | 브라우저에서 확대·축소, 레이어 선택, 지점 정보 확인. Leaflet 등 CDN 자원을 사용하는 인터넷 연결이 필요하다. 지도 타일 API 키는 필요 없다. |
| `rivers.geojson` | 대상 범위로 자른 실폭하천 면. 원본에 존재하는 표준 속성만 보존한다. |
| `sites.geojson` | 선택 지점 좌표와 표시용 속성. |
| `area.geojson` | 미리보기 사각형 또는 입력 유역 경계. `area_type`으로 구분한다. |

결과 폴더는 새 이름을 사용한다. 동일한 결과를 재현하도록 입력 파일 버전, 유역 코드와 출처, 사용한 명령을 연구 기록에 남긴다. 기존 분석 러너나 발표자료에 통합할 때는 검토가 끝난 GeoJSON을 해당 지도 화면의 하천 레이어로 연결한다. 발표자료의 하천 측정망 4곳은 이 CSV의 시설 지점과 별도로 관리한다.
