# 통합 수집 안내 (`Study/Data/통합수집.py`, 2026-11-26)

## 1. 한눈에

```
각 주제 폴더 수집 코드 ──(범위·저장 위치만 바꿔 실행)──▶ Study/Data/total/   (연구 범위, 2024~, 원본 형태)
                                                              │  덧붙이기(기존 행 그대로, 지점별 마지막 날 다음만)
                                                              ▼
                                     연구사업/data_tms/  수질자동측정망_data.csv, 하수폐수측정망_data.csv
                                     연구사업/data_weather/  weather_daily.csv, flow_daily.csv
```

- **기존 주제 폴더 자료는 그대로 둔다.** 통합 코드로 받은 자료는 `total/` 에만 쌓인다(주제 폴더 코드를 따로 실행하면 예전처럼 주제 폴더에 받는다).
- **total/ 시드(11-26)**: 처음 실행 때 기존 수집 자료에서 범위 안 것만 복사해 2024년부터 채웠다(하천 2024~25 일자료 2,319행 + 2026 원자료 31개 파일, TMS 사업장 원표 410개, ASOS 연도 파일 3개, 홍수통제소 관측소 63개).
- **연구사업 파일은 열·형식이 지금과 같다.** 분석 코드는 고치지 않는다. 분석 기간은 연구사업 `config.END`(지금 2026-06-30)가 정하므로, END 를 바꾸기 전까지 분석 결과는 같다.

## 2-1. 인증키 (2026-11-26 변경)

- 통합수집은 **`Study/Data/통합수집.env` 하나만** 읽는다(주제 폴더 `.env` 는 읽지 않음). 세 줄:
  `DATA_GO_KR_API_KEY=`(하천, 공공데이터포털) · `KMA_AUTH_KEY=`(기상청 API허브) · `HRFCO_KEY=`(한강홍수통제소). 방류수 TMS 크롤링은 키가 필요 없다.
- 처음 만들기·다른 PC: `python 통합수집.py --init-keys` → 주제 폴더 `.env` 에서 빠진 키만 복사(키 값은 화면에 안 씀). 주제 폴더 `.env` 가 없는 PC 는 `통합수집.env.example` 을 복사해 이름을 `통합수집.env` 로 바꾸고 키를 적는다.
- 키가 없으면 그 자료만 건너뛰고 고치는 법을 알려 준다. `--check` 표 위에 키 있음/없음이 나온다.
- 키를 새로 받으면 `통합수집.env` 를 고친다(주제 폴더 코드를 따로 돌릴 때는 그 폴더 `.env` 도 함께).
- `*.env` 는 `Study/.gitignore` 로 git 에서 빠진다(확인함). 주제 코드가 오류 문장에 요청 주소(키 포함)를 찍는 경우가 있어, 통합수집이 실행할 때는 화면 출력에서 키를 `***` 로 가린다. 주제 코드를 직접 실행할 때는 가려지지 않는다(기상청 코드에서 확인).

## 3. 명령

| 명령 | 하는 일 |
|---|---|
| `python 통합수집.py --check` | 받지 않고 total/ 와 연구사업 파일이 어디까지 있는지 표 |
| `python 통합수집.py --test` | 하천·기상·수위 API 연결만 확인(파일 안 바꿈) |
| `python 통합수집.py` | 하천·기상·수위 수집 → total/ 결합 → 연구사업 덧붙이기 |
| `python 통합수집.py --tms 2026Q4` | TMS 그 분기만 크롤링(크롬 필요) → total/ → 연구사업 |
| `--tms-refresh` | 이미 받은 사업장도 다시(잠정치 p → 확정치) |
| `--tms-include-open` / `--tms-show` | 끝나지 않은 분기도 조회 / 브라우저 창 보이기 |
| `--only river weather level` | 일부만 |
| `--merge-only` | 받지 않고 total/ 결합 + 연구사업 반영만 |
| `--no-research` | 연구사업 폴더는 건드리지 않음 |
| `--research-fill-gaps` | 연구사업 파일 기간 안에서 비어 있던 지점·날짜도 total 값으로 채움(기존 값은 그대로 — **분석 결과가 바뀔 수 있음**) |
| `--research-overwrite` | 연구사업 파일을 total 값에 맞춤: 겹치는 날 값을 바꾸고 빈 날도 채움(하천 2026 확정치, TMS 확정치 반영용 — **분석 결과가 바뀔 수 있음**). 11-26 부터 하천·TMS 도 기상·유량(merge_from_study)처럼 빈 날을 함께 채움 |
| `--init-total` | total/ 에 빠진 시드 파일을 기존 수집 자료에서 다시 채움(있는 파일은 안 건드림) |
| `--init-keys` | 주제 폴더 `.env` 의 인증키를 `통합수집.env` 로 모음(이미 있는 키는 그대로) |

결과: `Study/Data/통합수집_요약.md`(마지막 실행), **`total/수집이력.md`(받거나 합친 실행을 모두 쌓은 기록, 11-26 추가)**. `--check`·`--init-keys` 는 둘 다 남기지 않는다. 바뀐 연구사업 파일의 이전 판은 각 폴더 `_backup/<날짜시각>/`.

## 5. 연구사업 반영 규칙(덧붙이기)

- 하천: `data_tms/수질자동측정망_data.csv` 에 측정소별 마지막 날 다음 행만 붙임.
- TMS: `data_tms/하수폐수측정망_data.csv` 에 (사업장, 방류구)별 마지막 날 다음 행만 붙임. 잠정치 표시 p 는 떼고 숫자 문자열로. 같은 날 중복 행은 하나만(원표에 양주송추하수 2025-08-20·21 이 두 번 있음 — 기존 파일도 하나씩).
- 기상·유량: `연구사업/data_weather/merge_from_study.py --apply --study total` (기본 출처를 total 로 바꿈, 지점별 마지막 날 기준으로 바꿈).
- 연구사업 파일 안의 범위 밖 자료(경기도 다른 사업장, 다른 유량 관측소 등)는 그대로 남는다.
- **빈 날 경고(11-26)**: total 에는 있는데 연구사업 파일 기간 안에 없는 (지점, 날짜)가 있으면 `기존 기간 안 빈 날 N행 (안 붙임)` 으로 알린다. 예: 어느 달 API 가 늦게 열려 뒤 달만 먼저 붙은 경우. 채울지는 `--research-fill-gaps` 로 정한다.
- **동기화 충돌 사본(11-26)**: iCloud 등이 만든 `이름 2.csv` 같은 파일은 결합에서 빼고 경고한다(넣으면 행이 두 번 들어감).
- 분석 쪽은 `run.py` 가 실행마다 쓴 자료·기간·지문을 남긴다(`analysis_hantan_river/results/00_자료기준.md`, `실행이력/`). 자료를 붙인 뒤에는 **`python run.py` 전체**를 돌린다(일부 단계만 돌리면 옛 정제 자료를 읽어 경고가 나옴).
