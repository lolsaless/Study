# 강수량(기상) 자료 수집 개발지침

> 이 폴더의 수집 코드를 고치거나 새로 만들 때 이 문서를 먼저 읽는다. 최종 갱신 2026-11-17.
> 요청·응답 형식은 `강수량_API활용가이드.md`. 공통 규칙은 `Data/수질측정망/수질자료수집_개발지침.md` 3~5절과 같다.

## 1. 목적과 위치

- `Data/` 는 주제별로 **원자료를 수집·보관**하는 곳이다(수질측정망, 하천수질자동측정망, 하수폐수자동측정망, 강수량, 수위 …).
- 이 폴더(`Data/강수량/`)는 기상청 강수·기온 등 기상 원자료를 받는다. 분석은 연구 폴더(`연구사업/analysis_hantan_river/`)에서 하고, 여기서는 받기·정리·결합까지만 한다.
- 한강홍수통제소 우량계 강수량은 수위 코드가 함께 받으므로 `Data/수위/` 에 있다(`data/홍수통제소_우량_일자료.csv`).

## 2. 폴더 구조 (맥미니 `~/Documents/GitHub/Study/Data/강수량/`)

```
강수량/
├── 기상청_ASOS_일자료.py        기상청 API허브 ASOS 일자료 수집 코드
├── 기상청.env                    API허브 인증키 KMA_AUTH_KEY (밖으로 내보내지 않음)
├── .gitignore                    *.env, __pycache__ 제외
├── 강수량_개발지침.md            이 문서
├── 강수량_API활용가이드.md       API 요청·응답 형식
├── raw_data/기상청_ASOS/         연도별 받은 그대로: 2024.csv, 2025.csv, 2026.csv (실패 달이 있으면 YYYY_partial.csv)
├── data/                         기상청_ASOS_일자료.csv · 기상청_ASOS_weather_daily.csv · 기상청_ASOS_columns.csv
├── site_code/                    기상청_ASOS_지점.csv (지점번호·이름·위경도)
└── _backup/                      코드 수정 전 사본
```

- 받은 그대로 = `raw_data/`, 합친 것·설명표 = `data/`, 지점표 = `site_code/`.
- 새 출처(예: AWS 방재기상 일자료)를 붙이면 `raw_data/<출처>/` 하위 폴더를 새로 만들어 섞이지 않게 한다.

## 3. 수집 코드 현황

| 코드 | 대상 | 인증 | 결과 | 상태 |
|---|---|---|---|---|
| `기상청_ASOS_일자료.py` | API허브 `kma_sfcdd3.php` ASOS 일자료 56개 열, 전국(또는 `STATIONS`) | `기상청.env` → `KMA_AUTH_KEY` | 위 2절 | 가짜 응답으로만 시험(2026-11-17). 실제 호출 전 |

### 설정(코드 맨 위)
| 이름 | 기본값 | 뜻 |
|---|---|---|
| `START_DATE` | `"2024-01-01"` | 시작일 |
| `END_DATE` | `None` | 끝일, None = 어제(일자료는 전날까지) |
| `STATIONS` | `[]` | 빈 목록 = 전국 저장. 일부만: `[95, 98, 99]` |
| `REFRESH_DONE_YEARS` | `False` | 지난 연도도 다시 받기 |
| `RAIN_NEG_AS_ZERO` | `True` | weather_daily 파일에서 RN_DAY 음수를 0(비 안 옴)으로 볼지. **첫 실행 후 확정할 것** |

### 실행
```bash
cd ~/Documents/GitHub/Study/Data/강수량
python 기상청_ASOS_일자료.py --test        # 최근 한 주 응답 앞부분·읽은 결과·지점정보 출력
python 기상청_ASOS_일자료.py               # 수집 → 결합
python 기상청_ASOS_일자료.py --merge-only  # 결합만
```

### 동작 요약
- 한 달에 1번 요청, 전국 지점을 한꺼번에 받음(`stn=0`) → 2024-01 ~ 2026-11 약 35번.
- 연도 파일이 있으면 지난 연도는 건너뛰고, 올해는 매번 다시 받음. 실패한 달이 있으면 `YYYY_partial.csv`.
- 결합은 `raw_data/기상청_ASOS/` 의 연도 파일 **전체**를 합침(같은 연도에 완성본이 있으면 partial 은 제외).
- 응답의 `#  1. TM : …` 설명 줄이 10개 이상이면 그 이름을 열 이름으로 쓰고, 없으면 코드 안 56개 목록을 씀. 값 개수가 다르면 `COL_번호` 로 저장하고 경고.
- 지점정보: `stn_inf.php?inf=SFC` → `kma_stnlist.php` 순으로 시도, 둘 다 실패하면 코드 안 이름표(좌표 없음).
- 인증 오류(HTTP 401/403 또는 '인증 실패' 문구)는 즉시 중단.

### 결과 파일 열
| 파일 | 열 |
|---|---|
| `data/기상청_ASOS_일자료.csv` | `date`(YYYY-MM-DD), `stn`, `stn_name` + API 원래 열 56개(TM, STN, …, RN_DAY, …) — **값은 고치지 않음** |
| `data/기상청_ASOS_weather_daily.csv` | `stn, stn_name, date, rain_mm, source(ASOS), ta_mean, ta_min, ta_max` — 연구 폴더 `data_weather/weather_daily.csv` 와 같은 열 |
| `data/기상청_ASOS_columns.csv` | 열, 설명, 단위, 비고 |
| `site_code/기상청_ASOS_지점.csv` | `stn, stn_name, lat, lon, height_m, basin, law_id` |

weather_daily 파일에서만 바꾸는 값: 기온 -50 이하 → 빈칸(결측 코드로 봄, -9.0 은 실제 기온일 수 있어 그대로), RN_DAY 음수 → 0 또는 빈칸(`RAIN_NEG_AS_ZERO`).

## 4. 원칙(요약)

1. 설정은 코드 맨 위, 경로는 코드 폴더 기준(`Path(__file__).resolve().parent`).
2. 인증키는 `기상청.env` 에만. 변수 이름이 달라도 읽힘(KMA_AUTH_KEY → KMA_API_KEY → AUTHKEY … → 변수가 하나면 그 값).
3. 한글 파일명은 NFC 로 비교(맥 NFD 대응).
4. 원값 보존: raw·일자료 파일은 받은 그대로. 바꾼 값은 weather_daily 에만, 그 규칙은 columns.csv 에 적음.
5. CSV 는 `utf-8-sig`. 인텔 맥·맥미니·윈도우 모두에서 `requests pandas` 만으로 동작.
6. 코드를 크게 고칠 때는 `_backup/<이름>_<날짜>_before.py` 로 먼저 복사.

## 5. 첫 실행 후 확인할 것(미검증)

- [ ] `--test` 의 응답 앞 12줄: 설명 줄 형식, 값 구분(공백/쉼표), 줄 끝 `=` 여부, 글자 깨짐(EUC-KR)
- [ ] TM 형식이 `YYYYMMDD` 인지(결합 시 날짜를 못 읽으면 경고가 나옴)
- [ ] 'RN_DAY 값 분포': 비 안 온 날이 `0.0` 인지 `-9.0` 인지 → `RAIN_NEG_AS_ZERO` 확정
- [ ] 지점정보가 API 로 받아졌는지(좌표가 채워졌는지)
- [ ] 기온 열에 -99 같은 결측 코드가 있는지(요약 출력의 범위)
