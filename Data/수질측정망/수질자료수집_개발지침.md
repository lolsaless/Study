## 2. 기본 원칙

1. **설정은 코드 맨 위**: 기간(`START_YEAR`, `END_YEAR=None`=올해), 대상(대권역·지점·항목), 파일명을 맨 위 상수로 둔다. 사용자는 거기만 고친다.
2. **경로는 코드가 있는 폴더 기준**: `BASE_DIR = Path(__file__).resolve().parent`. 단, 사용자가 "실행한 폴더"라고 하면 `Path.cwd()`.
3. **인증키는 `.env`에만**: 코드·문서·결과 파일에 키를 쓰지 않는다. `.env` 이름은 사용자가 정한 것(예: `물환경.env`)을 따르고, 변수 이름이 달라도 읽히게 한다(여러 후보 이름 → 변수가 하나면 그 값). 인코딩 키는 `unquote()`.
4. **한글 파일명은 NFC로 비교**: 맥은 파일명을 NFD로 돌려줄 수 있다. `unicodedata.normalize("NFC", name)`으로 맞춰 찾는다.
5. **지점 목록은 CSV 코드표에서 읽는다**: 지점을 코드에 박지 않고 `물환경_수질측정망_지점코드_전체.csv`(열: 구분·지점코드·지점명·조사기관·주소·대권역·중권역)를 읽어 필터한다. 인코딩은 utf-8-sig → cp949 순으로 시도. 원본 xlsx는 더 쓰지 않는다. 자동측정망처럼 개수가 적으면 코드 안 사전으로 둬도 된다.
6. **XML로 받고 ElementTree로 읽는다**: 결과코드 `00` 확인, `03`/0건은 "자료 없음"으로 정상 처리, 게이트웨이 오류(키)는 즉시 중단.
7. **재시도·속도**: 요청 실패는 3~4회 재시도(대기 시간을 늘려 가며), 요청 사이 0.3초.
8. **이어 받기**: 단위(지점×월, 또는 연도)별로 저장하고, 다시 실행하면 받은 것은 건너뛴다. 단, 아직 공개 중인 최근 기간(자동측정망 약 3개월, 올해)은 매번 다시 받는다. 일부 실패한 단위는 `_partial`로 따로 저장해 완성본과 섞이지 않게 한다.
9. **원값 보존**: `-999`(정량한계 미만)·0·이상치는 고치지 않고 그대로 둔다. `n/a`·빈칸만 결측으로 바꾼다. 처리 방식은 열 설명에 적는다.
10. **저장 형식**: CSV는 `utf-8-sig`(엑셀에서 한글 안 깨짐). 엑셀이 필요하면 xlsx에 「자료」+「현황(기간·행수·결측률)」+「열설명」 시트. 열 이름은 API 원래 이름을 유지하고 설명표를 따로 낸다.
11. **결합 파일**: 단위별 파일을 다 받은 뒤 하나로 합치고(`all_data.csv` 등) 중복 행을 지운다.
12. **실행 안내**: 파일 첫머리 docstring에 준비물·결과·필요 패키지·실행 명령을 쓴다. 진행 상황은 `[연도] 묶음 n/N: 건수` 식으로 짧게 출력하고, 끝에 행 수·지점 수·최신 날짜를 출력한다.

## 3. 환경

- 사용자 기기: 인텔 맥(주 개발, Python 3.12, VS Code 가상환경), 맥미니, 윈도우 노트북. 세 곳 모두에서 돌아가야 한다.
- 패키지는 `requests pandas openpyxl python-dotenv` 정도로 제한. 최신 기능이 필요한 라이브러리는 피하거나 낮은 버전으로 고정.
- `from __future__ import annotations`는 파일 맨 위에만 둘 수 있다 → 설정 상수를 맨 위에 둘 때는 쓰지 않는다(3.10+라 `Path | None` 문법은 그냥 된다).

## 4. 시험과 보고

- 사용자가 "직접 테스트하지 말라"고 하면 API를 호출하지 않는다. 대신 `requests.Session.get`을 가짜 응답으로 바꿔 끝까지 돌려 저장·결합이 되는지 확인하고, 그렇게 했다고 정확히 말한다.
- 명세서와 실제가 다를 수 있는 부분(날짜 형식, 레이어 ID, JSON 구조)은 답변에 "첫 실행 후 확인할 점"으로 짧게 적는다.
- 코드표에서 확인한 사실(예: 한강 자동측정망 S01008·S01024 결번)은 코드 주석에 남긴다.
